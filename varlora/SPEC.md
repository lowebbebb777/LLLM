## 0. このプロジェクトの一行要約

Qwen2.5-Coder-7B に対し、有限要素法の変分原理（連続場⇄離散点の重み付き統合）を
構造的アナロジーとして借用した独自LoRAアダプタ `VariationalLoRA` を FFN層に適用し、
コード生成LLMの内部表現を改良できるかを **交絡を排した実験計画で検証する**。

---

## 1. 背景と目的

### 1.1 着想の出自
本アダプタの数理構造は、ユーザーが過去に開発した動的弾塑性き裂進展解析プログラム
(FORTRAN, 有限要素法) の変分原理サブルーチンに由来する。元コードの核心は以下の弱形式：

```
∫_Ω σ_ij·δε_ij dΩ = ∫_Γ t_i·δu_i dΓ
  内部仮想仕事(連続場)    外部仮想仕事(離散境界)
```

連続場(応力σ・ひずみε)と離散場(有限要素節点)を、形状関数 N_I(ξ) による
重み付き積分（ガウス求積 Σ w_g·f(ξ_g)）で整合させる構造を持つ。

### 1.2 NN設計へのアナロジー
| FEM側 | NN側への対応 |
|-------|-------------|
| 連続場 σ(x,y), ε(x,y) | 滑らかな分散表現を生む連続場アダプタ |
| 離散場 節点自由度 u_I | 局所的表現を生む離散場アダプタ |
| 形状関数 N_I(ξ), ΣN_I=1 | softmaxゲート（分割の単位性を保証） |
| ガウス求積 Σ w_g·f(ξ_g) | 求積点での重み付き統合 |

### 1.3 目的（スコープを厳密に限定）
- **やること**: 上記アナロジーをFFN層のLoRAアダプタとして実装し、効果を検証する
- **やらないこと**: J積分やvon Mises降伏条件など「具体的数式」のモデルへの埋め込みは対象外
- **狙い**: コード生成LLMの内部表現において、離散的構造（構文・トークン）と
  連続的構造（意味・数値）の扱いを構造的に強化できるか

## 2. VariationalLoRA の数理仕様

### 2.1 標準LoRAとの違い
標準LoRA: `W' = W + (α/r)·B·A` （単一の低ランク経路）

VariationalLoRA: 連続場経路と離散場経路の2系統を、入力依存ゲートで統合する。

### 2.2 forward の定義（擬似コード）
```
入力 x: [batch, seq, in_features]

# 2系統の低ランクアダプタ
cont = cont_B(cont_A(x))     # 連続場の寄与（体積積分項アナロジー）
disc = disc_B(disc_A(x))     # 離散場の寄与（節点和アナロジー）

# 形状関数ゲート（連続→離散の射影重み、ΣN_I=1を保証）
N = softmax(shape_fn(x), dim=-1)   # [batch, seq, n_quad]

# ガウス求積による統合
quad_weight = (N * quad_weights).sum(dim=-1, keepdim=True)  # スカラー化

# 変分原理的結合: 内部仕事(連続) + 境界仕事(離散)
out = quad_weight * cont + (1 - quad_weight) * disc
return (α/r) * out
```

### 2.3 必須の実装制約
- **ゼロ初期化**: `cont_B.weight` と `disc_B.weight` は zeros 初期化
  （学習開始時にアダプタ寄与=0、ベースモデルを壊さない。標準LoRA同様）
- **求積重み初期値**: `quad_weights` は `1/n_quad` で初期化（一様）。
  デフォルト `n_quad=3`（元コードの3点求積 WR3=0.1667 に対応）
- **ゲートの数値安定性**: softmax前のlogitに対し、必要なら温度パラメータτで
  スケール（`softmax(logit/τ)`）。NaN対策（後述§6）の主要ポイント
- `cont_A, disc_A, shape_fn` は通常の線形層初期化（kaiming or 標準）

### 2.4 パラメータ数（交絡対照の設計に必須なので明記）
in=d, out=d, rank=r, n_quad=q のとき:
```
cont_A: d·r,  cont_B: r·d   → 2dr
disc_A: d·r,  disc_B: r·d   → 2dr
shape_fn: d·q
合計 ≈ 4dr + dq  （標準LoRA rank=r の約2倍 + dq）
```
→ **条件B（交絡対照）では、標準LoRAのrankをこの値に一致するよう拡大する**こと。

## 3. 適用対象

### 3.1 ベースモデル
- `Qwen/Qwen2.5-Coder-7B`（HuggingFace）

### 3.2 適用層（FFN層のみ）
- 対象モジュール名: `gate_proj`, `up_proj`, `down_proj`
- **Attention層 (q/k/v/o_proj) には適用しない**
  - 理由: FFNはトークン独立の非線形変換であり、要素ごとのガウス求積アナロジーと
    構造的に最も整合する。Attentionへの適用は勾配が不安定になりやすく、
    RTX 3060のデバッグ反復回数が限られる中ではリスクが高い

### 3.3 量子化
- 4bit量子化（QLoRA構成）。`BitsAndBytesConfig`:
  - `load_in_4bit=True`
  - `bnb_4bit_quant_type="nf4"`
  - `bnb_4bit_compute_dtype=torch.float16`
  - `bnb_4bit_use_double_quant=True`（VRAM節約）

## 4. 実験計画（★最重要・省略禁止★）

### 4.1 設計思想
「VariationalLoRAで性能が変わった」が、変分原理アナロジーの効果なのか、
単なるパラメータ増加なのかを**区別できなければ意味がない**。
全条件で**総学習可能パラメータ数を揃える**ことで交絡を断つ。

### 4.2 4条件
| 条件 | 内容 | 役割 |
|------|------|------|
| **A** | 標準LoRA (rank=r₀) | ベースライン（対照群） |
| **B** | 標準LoRA (rank拡大でCとパラメータ数一致) | 交絡対照（「増えただけ」を分離） |
| **C** | VariationalLoRA (ゲート動的) | 実験群（本仮説） |
| **D** | VariationalLoRA (ゲート固定0.5) | 機構分離（ゲート動的性の寄与を分離） |

- r₀ は手応え確認フェーズで決めた値（例 r₀=16 など）
- 条件D: `quad_weight` を学習させず定数0.5に固定（cont と disc を等weightで合成）

### 4.3 仮説の成立条件
```
C > B  かつ  C > D  が両方成立 → 「変分原理アナロジーに効果あり」と主張可
C > A だが C ≈ B    → 効果はパラメータ増加によるもの（アナロジーは無関係）
C ≈ D               → ゲートの動的性は不要（固定でよい）
```

### 4.4 統制すべき変数（全条件で固定）
- データセット（同一）、エポック数、learning rate、warmup、seed、
  バッチ構成、評価プロトコル、評価seed
- seedは最低3つで反復し、分散を見ること（1回の結果で優劣を断じない）

## 5. 検証基準（何で「内部表現が改良された」と判定するか）

### 5.1 タスク（両方で多面的に）
1. **コード生成ベンチ**: HumanEval（pass@1, pass@10）, MBPP
2. **数値・統計タスク特化の自作評価セット**: §5.2参照

### 5.2 自作評価セット（数値・統計の内部表現を測る）
LLMが数値・統計を「文字列」でなく構造として扱えているかを測る問題群。例:
- プロセス能力指数(Cp/Cpk)を計算するコード生成
- 統計手法(回帰・分類・検定)の正しい実装
- 数値の桁・スケールに関する一貫性（12.34を正しく数として扱うか）
- 離散(カテゴリ/フラグ)と連続(実数)が混在する処理の正しさ
- 50〜100問程度。pass@1とは別に「数値整合性スコア」を定義する

### 5.2b 経路独立性スコア（J積分の経路独立性アナロジー）★全機構共通の検証軸★
**出自**: 動的J積分の経路独立性。元コードは複数の積分経路（NPTH=1,NPATH）で
J値を計算し、経路によらず一致することを物理的正しさの判定に使う。

**LLMへの転用**:
```
FEM:  異なる積分経路 Γ1,Γ2,... で J計算 → 一致すべき（しなければ解が不正）
LLM:  同じ問題を異なる「経路」で解く → 同じ答えに到達すべき
      経路 = 言い換え / ステップ順序変更 / 異なる中間表現
```
- 内部表現が頑健（経路独立）なら、表層的な言い換えに対し答えがブレない
- **反証可能な予測**: VariationalLoRA等が内部表現を真に改良したなら、
  経路独立性スコア（言い換え耐性）が標準LoRAより向上するはず
- 実装: 各評価問題に対し N通りの言い換え/順序変更プロンプトを用意し、
  答えの一致率（または分散の小ささ）を経路独立性スコアとする
- M1/M3/M4のすべてで、この軸を共通の検証指標として測定する

### 5.3 判定の作法（製造QAのDOEと同じ厳密さで）
- 各条件×3seed の結果を集計、平均±標準偏差で報告
- 条件間の差が標準偏差の範囲内ならノイズとみなす
- HumanEvalが1%上下しただけで結論しない。効果量で語る

## 6. 環境制約と既知の落とし穴（RTX 3060 12GB）

### 6.1 ハードウェア
- GPU: RTX 3060 (12GB VRAM), RAM 32GB, Ubuntu
- Windows併用環境のため、最終的にWindowsでの推論展開も想定（GGUF変換）

### 6.2 VRAM管理（OOMはほぼ確実に最初に出る）
- `gradient_checkpointing=True` 必須
- 初期 `per_device_train_batch_size=1`, `gradient_accumulation_steps=8〜16`
- `max_seq_length` は 1024〜2048 から開始（長いとOOM）
- OOM時の調整順: seq_length↓ → batch据え置きでgrad_accum↑ → rank↓

### 6.3 勾配のNaN（VariationalLoRA特有のリスク）
- softmaxゲート + 二重アダプタは4bit下で勾配が暴れやすい
- 対策:
  - `max_grad_norm=1.0`（gradient clipping）必須
  - softmax温度τの導入（logitスケール調整）
  - 学習初期は learning rate を小さめ（例 1e-4 から）
  - lossにNaN検知を入れ、出たらそのstepのstate/inputをダンプ

### 6.4 パッケージ
- `pip install` 時 `--break-system-packages` が必要な環境
- torch (CUDA 12.x対応版), transformers, peft, bitsandbytes, accelerate, trl, datasets
- bitsandbytes はCUDAバージョン整合に注意（Windows側は別途確認）

## 7'. 拡張マイルストーン（M2成功を前提に積み上げる）

> 以下M3〜M5は、いずれも元のFORTRAN動的弾塑性FEMコードから抽出した
> 数理体系の一般化である。**前段の成功を前提に、一度に1機構ずつ**追加する。
> 各機構は必ず「単体 vs パラメータ数一致の標準LoRA対照」で独立検証し、
> 交絡（効果がパラメータ増加由来か機構由来か）を断つこと。

### M3: ComponentSeparatedLoRA（成分分離法のアナロジー）
**出自**: `tintegy.f` の動的J積分成分分離。全体積分を領域種別（NFLAG:
NORMAL/INTF/ICRK）ごとに分離・積算し、後で再合成する構造。

**数理アナロジー**:
```
J_total = J_volume + J_surface + J_interface + J_crack  （加法的分解）
出力 = Σ_c  route_c(x) · component_c(x)
```
- VariationalLoRAの2成分（連続/離散）を **N成分に一般化**したもの
- 各成分に**意味を割り当てて設計**する（例: 構文/数値/制御フロー）。
  ここが通常のMoEとの差別化点＝**解釈可能性**
- ルーティング（`router`）はNFLAGによる領域分類のアナロジー

**実装上の制約**:
- `n_components` はRTX 3060では 2〜3 が現実的上限（4以上はVRAM圧迫）
- 各成分 `comp_B` はゼロ初期化
- **mode collapse対策必須**: softmaxルーターは1成分に全振りされやすい。
  MoEのauxiliary loss（負荷分散loss）を導入し、成分が均等に使われるよう促す

**検証（交絡を断つ）**:
| 条件 | 内容 |
|------|------|
| M3-A | 標準LoRA（パラメータ数をM3-Cに一致） |
| M3-C | ComponentSeparatedLoRA（意味割当・動的ルーティング） |
| M3-D | 同・ルーティング固定（均等重み） |
- M3-C > M3-A かつ M3-C > M3-D で「成分分離に効果あり」
- **解釈可能性の定量化**: 各成分が実際に割り当てた意味（構文/数値/制御）に
  対応した入力で発火しているかを分析。これが示せて初めてMoEに対する新規性

**第二の動機（計算効率・疎性アナロジー）— ★実装はM3着手時まで保留★**:
> この観点は動機としてここに記録するのみ。M0〜M2の手応えを見る前に
> 実装へ盛り込まない（複雑性が勝つため）。M3着手時に判断する。

- 背景: 密行列演算（Attention/FFN）はGPUのSIMT特性上、ゼロ要素を
  あえてスキップしない（warp divergenceを避けるため全要素を計算する方が速い）。
  つまりLLMには「ゼロ領域を本当に飛ばす」構造がそもそも乏しい。
- 対比: FEMの剛性行列（元コードの EMASS / UPPHLF / MDV 等）は疎行列であり、
  繋がっていない節点間のゼロを構造的に飛ばす（スカイライン/バンド/疎ソルバ）。
  **「ゼロを飛ばす」発想はFEMでは常識だが、密なLLMには欠けている。**
- 転用案: ComponentSeparatedLoRAのルーティングを**ハードに**判定し
  （「この成分は発火しない」を確定）、該当成分の計算を実際にスキップする。
  = MoEの条件付き計算を、破壊力学の疎性アナロジーとして設計する。
- これはM3の解釈可能性とは別軸の**計算効率という第二の新規性**になり得る。
- 実装上の注意（着手時に対処）: ハードルーティングは勾配が流れにくい。
  Gumbel-softmax / Straight-Through Estimator 等で微分可能性を確保する必要。
  → だからこそM0手応え前には入れない。

### M4: NewmarkLoRA（時間積分法のアナロジー）★転用B=層方向が本命★
**出自**: ニューマークβ法・ウィルソンθ法（構造動力学の時間積分）。

**数理アナロジー（層方向＝深さ方向の更新）**:
```
Transformerの残差接続  x_{l+1} = x_l + F(x_l)  はオイラー陽解法(β=0)と等価。
層深さを「時間ステップ」とみなし、残差更新を高次積分スキームに拡張する:

  x_{l+1} = x_l + velocity(x_l) + β·accel(x_l)
                  1階項          2階項（β重み）

β = 過去/未来の混合比（学習可能、sigmoidで0〜1に制約）
  β=0   → オイラー法（標準Transformer残差）
  β=1/4 → 平均加速度法アナロジー（無条件安定の構造的対応）
```
- **本命は転用B（層方向更新）**。理由: 今のFFN×QLoRAの土俵を保ったまま実装可能
- 系列方向（転用A）はMamba/SSMアーキテクチャ変更になるため**本SPECの対象外**
  （別プロジェクトとする）

**θ法オプション（正則化）**:
- ウィルソンθ法の数値減衰（高周波dampening）を**正則化項**として転用
- 細かいノイズ的変動を抑え大局的意味構造を保持。過学習対策・頑健性向上
- M4のオプションフラグとして実装（デフォルトoff、M4本体の検証後に試す）

**検証（交絡を断つ）**:
| 条件 | 内容 |
|------|------|
| M4-A | 標準LoRA（パラメータ数をM4-Cに一致） |
| M4-C | NewmarkLoRA（β学習可能・1階+2階項） |
| M4-D | NewmarkLoRA（β=0固定＝オイラー法、2階項は持つが使わない） |
- M4-C > M4-A で「2階項（加速度）追加に効果あり」
- M4-C > M4-D で「βの動的性（高次積分）に効果あり」
- βの収束値を観察（0付近に収束するなら高次化は不要という知見）

### M5: 統合と最終結論
- M1〜M4で個別に効果が確認された機構のみを組み合わせる
- 全機構同時投入時の**相互作用**を分析（相乗/相殺/冗長のいずれか）
- 機構間の交絡を避けるため、組み合わせは段階的に（C単独→C+成分→C+成分+時間）
- 最終的に「破壊力学の数理体系（空間=変分・分解=成分・時間=積分・
  検証=経路独立）のLLM移植」として一貫した結論をまとめる
